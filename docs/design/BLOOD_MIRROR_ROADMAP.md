日期：2026-10-10。狀態：M1 已驗證並以 `7359fc1` 推送遠端 main；後續項目為提案，尚未完成。

## 方向與範圍

以目前 LUCAS LAB 原生 JavaScript 網頁遊戲為基礎，改善繼續遊玩、重返遊戲、重玩、UI 與美術品質。使用者允許必要的大範圍架構變動；是否改造應由實際玩法與維護需求決定。原作正文與遊戲改編分開維護。

依據：`games/blood-mirror/engine.js`、`app.js`、`challenges.js`、`index.html`、`MEDIA_ASSETS.md` 與 `docs/design/UI_COVER_PLAN.md`。已確認五幕、五種互動謎題、三結局、本機存檔與藝廊。未取得真人試玩、留存率或原研究成果，不能把設計推測當成已證實缺點。

## 第一批實作邊界

- `journey.js` 只從既有 state 與互動謎題完成狀態產生呈現資料。
- 首頁回顧不揭露未探索內容；遊戲中建議復用探索、封印、旅行與結局事件。
- 筆記只列已查看內容與已解鎖章節，預設目前章節，也可看全部。
- 不變更 `blood-mirror-v1`、`blood-mirror-challenges-v2`、`blood-mirror-ui-v1` 格式。
- 不改謎題答案、王后三問規則、結局條件、原稿、素材或音樂授權。

## 後續設計提案與待決事項

1. **魔鏡招牌玩法：有條件適合。** 用同一場景的現實／倒影差異推理；先做單一謎題原型，確認容易理解並與既有故事相容。
2. **證據關聯：有條件適合。** 連結兩項筆記取得新推論；避免所有謎題都變成拖拉配對。
3. **人物記憶：適合先小規模驗證。** 可選探索補足角色理解，不讓主線因遺漏收藏無法前進。
4. **王后三問：待決。** 目前為固定正解；保留時明示還原證詞，改為自由選擇則需要真正不同的反應與後果。
5. **雙層封印：待試玩。** 管網修復後再輸入順序；觀察是否有新價值，再選擇整合或保留。
6. **架構：依需求演進。** 可先將大型 app 拆成旅程、探索、筆記、謎題與結局控制。複雜分支成立後再設計統一狀態與版本遷移；目前沒有證據需要更換框架或加入雲端服務。
