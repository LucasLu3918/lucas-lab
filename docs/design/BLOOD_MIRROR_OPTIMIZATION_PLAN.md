# 《白雪公主：血色魔鏡》完整優化方向

日期：2026-10-10｜狀態：方向規劃，尚未實作後續功能。

## 目標與現況

將現有網頁解謎雛形逐步提升為有辨識度、操作舒服、值得完成與重玩的暗黑童話遊戲。黏著度分成三個目標：第一次願意繼續玩、中斷後願意回來、通關後願意重新探索。以玩家的實際動機與體驗驗證，避免只靠增加題數或收藏數量延長時間。

已確認基礎：五幕場景、五種互動謎題、文字封印、三結局、本機存檔、分層提示、筆記、藝廊與配樂。旅程回顧、下一步引導及章節筆記篩選已在提交 `7359fc1` 推送遠端 main。現況依據為原始碼與 `MEDIA_ASSETS.md`；尚無真人留存或試玩統計，不把推測列為已證實問題。

本文件列出主要實作方向與驗收重點，不是細部規格、工期承諾或立即實作授權。使用者允許必要時大幅改造架構；具體改造程度依原型與相依性決定。保留完整原稿，遊戲改編另行設計。新增劇情、分支數、美術方向與跨裝置資料服務在昂貴製作前仍需確認。

優先級：**P0** 建立證據與標準；**P1** 完成一幕樣板與全程基本品質；**P2** 深化玩法與重玩；**持續** 每次更新均需處理。功能適配性基於目前原生 JavaScript、五幕故事與本機存檔架構；有條件適合者先驗證，不一次全面導入。

## A. 玩家體驗與核心玩法

### 01｜玩家定位與體驗基線（P0／適合）

- **目的：**確認要服務的玩家、主要裝置、故事與解謎的比例，以及一次遊玩的理想節奏。
- **主要工作：**招募少量新手與熟手試玩，觀察離開位置、卡關原因、提示使用、操作困惑和想重玩的理由；保留現有受歡迎內容。
- **完成標準：**形成目標玩家、體驗定位、現況問題與保留清單。先取得基線，再訂改善數值，不先假設留存目標。

### 02｜開場、教學與前幾分鐘（P1／適合）

- **目的：**讓新玩家快速知道扮演誰、為何探索、如何互動，並儘早獲得第一次有意義的發現。
- **主要工作：**用場景行動帶出探索、收取、筆記與解謎；調整序章資訊量；讓提示在需要時出現；確認下一步建議不壓縮自由探索的樂趣。
- **完成標準：**未玩過的新玩家能自行開始第一幕，理解任務與基本操作，不需要另看長篇說明。

### 03｜探索與互動的核心循環（P1／適合）

- **目的：**建立「觀察→發現→推理→操作→看到後果→產生新問題」的遊玩節奏。
- **主要工作：**讓道具、場景與謎題互相連動；解題後改變場景、揭露證據或觸發角色反應；提供適量可選探索。
- **完成標準：**玩家能說出自己的操作帶來什麼改變，每幕都有探索與突破，而非只依序打開文字視窗。

### 04｜謎題品質、難度與雙層封印（P1／適合）

- **目的：**使解謎公平、與故事有關，也避免連續完成性質相近的工作。
- **主要工作：**檢查每題的線索、推理、操作、回饋與提示；評估互動謎題與文字封印是否各有價值，特別是蒸汽管修復後的順序操作；建立難度曲線。
- **完成標準：**玩家卡關主要來自推理，解答後能理解原因；保留或整合雙層封印有試玩依據；記憶類題目可調整節奏或提供替代協助。

### 05｜魔鏡招牌玩法（P2／有條件適合）

- **目的：**讓作品擁有與魔鏡、名字和記憶主題直接相關的玩法辨識度。
- **主要工作：**原型驗證現實與倒影差異、鏡中資訊、記憶復原等方向；選擇最清楚且能反覆演進的一套規則。
- **完成標準：**玩家能理解並運用魔鏡規則，在後續關卡有新的發現；先完成單題原型與試玩，再決定是否套用全遊戲。

### 06｜道具、證據與筆記的連動（P2／有條件適合）

- **目的：**讓物品與筆記能支援思考，增加探索深度。
- **主要工作：**明確呈現道具用途、可使用對象與使用結果；評估將兩項證據連結產生推論；筆記區分已知事實、未解問題與人物關係。
- **完成標準：**玩家能從已取得資訊找到下一個推論，無需盲目對每個物件嘗試；證據連結不變成重複的配對勞動。

### 07｜五幕特色與全程情緒節奏（P1→P2／適合）

- **目的：**讓每幕都有不同的探索重點與情緒，不只有背景和小遊戲不同。
- **主要工作：**書庫聚焦身份與契約；礦坑聚焦修復與生命代價；棺室聚焦意識與記憶；寢宮聚焦王后證詞；鏡國聚焦真相與最後交易。穿插探索、解謎、揭露與喘息。
- **完成標準：**玩家能描述各幕的特色；重要揭露有前面證據支撐；高潮沒有被過長的重複操作打斷。先以黑鐘書庫建立完整樣板。

## B. 故事、自主性與重玩

### 08｜劇情改編、人物與世界觀（P1→P2／有條件適合）

- **目的：**讓玩家透過遊玩理解角色與代價，保留原作辨識度。
- **主要工作：**整理原作與遊戲事件對照、人物動機與資訊揭露順序；將必要敘事放入可探索證據；補足王后、礦工、孩子與白雪的情感連結。
- **完成標準：**玩家理解主要衝突與人物行動；可選內容增加理解但不阻斷主線；新內容與既有原作一致，改編尺度先確認。

### 09｜有意義的選擇與分支（P2／有條件適合）

- **目的：**讓玩家的選擇產生能理解的後果。
- **主要工作：**明確區分「還原角色的既定回答」與「玩家自由選擇」；先處理王后三問的定位；用少量途中決策、證據或準備影響後續反應。
- **完成標準：**選項符合畫面承諾，選擇不只是猜作者答案；各分支可通關且結果有因果；新增分支數量和舊存檔處理先設計。

### 10｜結局與情緒收尾（P2／有條件適合）

- **目的：**讓結局回應整段旅程，而不只是在最後選單查看三段文字。
- **主要工作：**檢視目前三結局的準備、選擇與代價；評估途中行動對收尾的影響；加入合適的畫面、聲音與旅程回顧。
- **完成標準：**玩家能解釋自己為何得到該結果；主要情緒有完整收束；保留方便回看結局的能力，新條件不懲罰缺乏說明的玩家。

### 11｜回訪、重玩與收藏（P2／有條件適合）

- **目的：**在 M1 回訪功能之上，讓通關後有值得重新探索的內容。
- **主要工作：**設計可選人物記憶、不同證詞、場景變化、圖鑑或少量成就；提供不劇透的未探索方向；評估章節重玩和已讀內容快進。
- **完成標準：**重玩能獲得新的理解或體驗，收藏有內容價值；回顧與重玩不誤覆寫旅程；先測試理由成立，再增加內容量。

## C. UI、美術與聲音

### 12｜遊戲 UI 與資訊架構（P1／適合）

- **目的：**兼顧沉浸感與清楚操作，讓場景、目標、道具、筆記、提示各有位置。
- **主要工作：**建立遊戲專用元件與狀態規則；檢查工具列、彈窗、背包和場景切換；減少重複開關與捲動；保持選取、停用、成功、失敗的清楚回饋。
- **完成標準：**玩家看得懂可操作區與目前狀態；手機和桌面都能流暢完成同一流程；風格一致且排版不因互動跳動。

### 13｜視覺風格與角色一致性（P0→P1／適合）

- **目的：**建立能長期擴充的美術標準，讓新圖能融入既有作品。
- **主要工作：**以現有暗黑童話方向整理色彩、材質、光影、字體；建立白雪與主要角色設定、表情和服裝參考；先做一幕視覺樣板。
- **完成標準：**主要角色在不同圖中可辨識；UI 與場景同屬一套視覺語言；量產素材前確認樣板，避免大量返工。

### 14｜正式場景、道具與結局素材（P1→P2／適合）

- **目的：**讓素材品質、互動位置和情緒橋段支持實際遊玩。
- **主要工作：**逐幕補齊完整背景、必要場景變化與獨立道具圖；替換不適合遊玩的概念展板取景；補齊霜潮和王冠的完整 CG，並統一三結局品質。
- **完成標準：**重要互動在小螢幕仍可辨識；圖像裁切與命中區對齊；素材有足夠尺寸、正確來源及載入備援；圖上的文字由介面排版。

### 15｜動態回饋與場景演出（P1→P2／有條件適合）

- **目的：**讓收取、解開、修復與揭露真相具有可感知的變化。
- **主要工作：**設計少量道具回饋、蒸汽運作、鏡面變化、場景轉場與高潮演出；依節奏服務資訊和情緒。
- **完成標準：**玩家知道發生了什麼；動畫不妨礙操作、閱讀與載入；支援減少動畫，主要演出不阻擋反覆遊玩。

### 16｜配樂、音效與聲音控制（P1→P2／適合；配音另評估）

- **目的：**建立每幕與結局的情緒，並用聲音支援操作回饋。
- **主要工作：**將短版試聽配樂逐步換成適合場景的正式循環版本；整理音量、淡入淡出與環境聲；區分音樂／音效控制。角色配音先以少量關鍵台詞驗證。
- **完成標準：**循環自然、切換不突兀、音量不互相蓋過；返回分頁與靜音行為穩定；靜音仍能取得全部必要資訊。來源與公開使用條件先確認。

## D. 技術品質與可持續製作

### 17｜存檔、重玩與版本相容（P1→P2／適合）

- **目的：**支援長期更新，讓玩家可靠地延續或重玩旅程。
- **主要工作：**規劃故事進度、互動謎題進度、收藏與設定的責任邊界；評估尚未完成謎題的保存、章節重玩、存檔匯出／匯入；新增分支前建立版本遷移。
- **完成標準：**舊存檔、損壞資料與無法儲存有明確處理；重設範圍清楚；不同版本升級有測試與復原方案。跨裝置同步另行評估。

### 18｜載入速度與裝置相容（P1／適合）

- **目的：**讓手機與一般網路也能順利開始和完成遊戲。
- **主要工作：**檢查圖片與音訊大小、必要素材預載、其餘延後載入；處理載入中／失敗狀態；驗證 iOS Safari、Android Chrome 與主要桌面瀏覽器。
- **完成標準：**關鍵素材可載入、切換不出現無說明空白；用實測訂立載入預算；觸控、背景分頁、音訊及儲存限制有驗證。

### 19｜可讀性與無障礙操作（P1／適合）

- **目的：**讓不同操作習慣與視覺需求的玩家能完成主要流程。
- **主要工作：**檢查文字、對比、焦點、鍵盤與觸控；狀態不只依賴顏色；記憶閃爍與聲音題提供適當協助；保持字級與減少動畫設定一致。
- **完成標準：**重要流程可用鍵盤與觸控完成；必要資訊可讀；設定對謎題與筆記生效；自動檢查與真人裝置測試分開記錄。

### 20｜模組架構與內容製作流程（P1→P2／有條件適合）

- **目的：**讓新增關卡、分支與素材容易維護，避免每次修改牽動整個 app。
- **主要工作：**依需要拆分旅程、場景、筆記、謎題、結局與音訊控制；統一狀態變更入口；整理內容資料、謎題介面、素材清單與建置驗證。
- **完成標準：**新增一幕能沿用已定義的介面與資料規則；模組責任清楚；重構前後流程和存檔可驗證。框架更換以實際需求為依據。

### 21｜測試、試玩與改善判定（持續／適合）

- **目的：**確認功能正確，也知道是否更好玩。
- **主要工作：**持續測試解鎖、道具、分支、存檔與跨裝置流程；用新手／熟手試玩追蹤理解、卡關、參與、情緒與重玩理由；每批比較修改前後。
- **完成標準：**測試與真人觀察都有紀錄，每次改善能對應問題與效果；先以人工／本機紀錄取得證據，若需要遙測再確認資料範圍與保留方式。

### 22｜發布、素材管理與作品呈現（持續／適合）

- **目的：**讓遊戲版本、素材來源、入口和公開介紹保持可信且可維護。
- **主要工作：**維護發布紀錄、回復方式、main 驗證和正式站巡檢；整理素材原檔、遊戲版本及來源；更新遊戲介紹與內容提示，使宣傳符合實際玩法。
- **完成標準：**知道正式站對應哪個提交；可定位素材與版本；新增內容後介紹沒有過期資訊；公開素材的使用條件已確認。

## 建議批次與相依順序

1. **建立基準：**01、13，並啟動 21。先確認玩家、問題與視覺標準。
2. **完成黑鐘書庫樣板：**02、03、04、07、12、14、15、16；同步驗證 18、19。玩法、UI 與美術整合後才擴到其餘四幕。
3. **深化五幕：**05、06、07、08；依複雜度進行 20。魔鏡與證據玩法先驗證單題原型。
4. **建立重玩：**先確認 09 的分支方案與 17 的存檔處理，再進行 10、11。避免先做大量分支素材，再回頭重寫邏輯。
5. **整體打磨：**補齊 13–19；21、22 貫穿所有批次。每批獨立驗收，不必等全部方向完成才發布。

## 可選擴充，暫不列入必做

| 方向 | 評估條件 |
| --- | --- |
| 多語系 | 有海外玩家需求，且能維護劇本、謎題與 UI 翻譯；先整理文字資源 |
| 離線／PWA | 玩家確實需要離線，且能處理大型音訊、更新快取與存檔版本 |
| 帳號與雲端存檔 | 跨裝置需求成立後，再確認成本、資料、權限及同步衝突 |
| AI 自由對話魔鏡 | 只有在受控對話不足以滿足玩法時評估；先驗證劇透控制、延遲、成本與資料處理 |
| 社群、排行、每日任務 | 先驗證是否符合目前敘事解謎體驗與玩家需求，不預設納入 |

## 後續拆分規則

每次只選一個批次，再拆成可驗收的工作卡：問題／依據、預期玩家感受、最小原型、內容與素材、相依項目、測試、工作量、存檔與復原影響。遇到會影響故事方向、分支規模、美術定調、資料或成本的決策再確認；低層實作細節由實作方處理。
