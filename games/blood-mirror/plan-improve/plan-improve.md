## 0. 一頁摘要

**問題**：目前版本是「網頁裡的遊戲」，不是「遊戲」。場景圖在手機第一屏看不到，熱點直接寫出名字，答案多半是「讀到文字 → 照抄」，五幕各只有一張場景圖，實際首玩時間估計只有 18–28 分鐘，配樂是 30 秒的試聽片段反覆循環。

**方向**：保留現有的哥德式暗紅＋古金美術、五幕故事骨架與三個結局，把體驗改成三件事：

1. **摸得到的機關**（借鏡《The Room》）：每幕 2–3 個視角與特寫，物品能檢視、組合、在場景中使用。
2. **自己推理出真相**（借鏡《The Case of the Golden Idol》）：每幕結尾的「魔鏡審問」用蒐集到的線索詞填空，答對才算看穿謊言。
3. **環環相扣的祕密**（借鏡《Rusty Lake》）：跨章節的伏筆、隱藏的鏡之碎片、選擇在尾聲留下回聲。

**結果目標**：首次通關 45–60 分鐘（快速玩家下限 ≥ 32 分鐘），全收集 75–90 分鐘；手機直向與桌面都是「滿版舞台」體驗。

**拆分**：九個里程碑（M0–M8），每個都能獨立合併、獨立驗收。**A 階段（M0–M5）結束時就達到 30 分鐘以上**；B 階段新增兩個章節；C 階段做收藏、重玩與最終打磨。

## 1. 現況診斷

### 1.1 內容量與時長

| 項目 | 現況 | 證據 |
|---|---|---|
| 章節 | 5 幕，每幕 1 張場景圖 | `engine.js` 的 `rooms` |
| 每幕互動 | 4–6 個熱點、1 個互動謎題、1 個文字封印 | `rooms[].spots`、`challenges.js` |
| 解法型態 | 多為照抄文字：`1373`、冷水→熱泉→城市、月亮→蘋果→鏡子、選「白雪公主」 | `rooms[].answer` 與 `hints` |
| 首頁宣稱 | 約 25–40 分鐘 | `index.html` 的 `.game-meta` |
| 估計實際首玩 | 18–28 分鐘（讀序幕 0.5 分＋探索 1.5–2 分＋謎題 1–3 分＋封印 0.5 分，五幕） | 推估，尚無真人資料 |

> 已有 `playlog.js`（自願開啟的單人試玩紀錄），可直接用來量每幕耗時。M0 先請 3 人試玩、取得基準值，避免憑感覺。

### 1.2 UI/UX

實際在 1280px 與 375px 開啟 `/games/blood-mirror/play/` 觀察到：

- **場景不是主角**：375px 手機上，場景要捲到約 660px 才出現；上方依序是站台列、遊戲標題列、工具列、目標卡、下一步建議卡。桌面版場景只占畫面約 1/3。
- **沒有「發現」的樂趣**：熱點是直徑約 44px 的圓圈加中文標籤，一進房間就全部看得到。
- **過度引導**：「下一步建議」常駐並附快捷按鈕，玩家不需要思考就能點完全程。
- **敘事被擠到側欄**：劇情文字放在右側欄，手機上在場景下方，閱讀與觀看無法同時發生。
- **網站外框**：站台導覽、首頁、章節卡與遊戲本體在同一頁切換，進入遊戲沒有「進入另一個世界」的儀式感。

### 1.3 音訊

- 9 首配樂都是約 31–36 秒的試聽版，持續循環很快就會聽出重複。
- 備援是 WebAudio 合成音；音效只有少數 `playCue`（例如收取物品），沒有環境音層。
- 只有一個總開關，沒有音樂／音效／環境分軌音量。

### 1.4 技術與架構

- `app.js`（39 KB）、`engine.js`（23 KB）以超長單行撰寫，內容資料（劇情文字）與規則混在同一檔，新增章節的成本高。
- 進度分散在兩個 localStorage 鍵：故事 `blood-mirror-v1` 與互動謎題 `blood-mirror-challenges-v2`；`restoreState` 寫死 5 幕（`n<5`）。
- 謎題以 `room.id` 寫死在 `challenges.js`，沒有共同介面。
- **資產預算已接近上限**：`scripts/check.cjs` 規定 `dist/games ≤ 11 MB`、單一 MP3 ≤ 2.5 MB；目前 `dist/games` 約 10 MB，其中音樂 7.9 MB（`highlights.mp3` 就占 2.35 MB）。新主題曲母帶 9.3 MB，無法直接放入。

### 1.5 優點（必須保留）

- 美術方向一致：哥德式暗紅絲絨、古金巴洛克、燭光與冷藍月光。
- 劇本紮實：改編自 20 章完整原著，角色動機清楚，三結局有道德重量。
- 無障礙基礎好：鍵盤操作、Esc／焦點回復、減少動畫、較大文字、44px 點擊區。
- 零相依、嚴格 CSP、離線可玩、存檔可匯出——這些工程紀律在重構時不能退步。

## 2. 參考遊戲分析

挑選標準：同為「解謎＋敘事」、手機與桌面都廣受好評、核心樂趣能移植到網頁 2D。

### 2.1 《The Room》系列（Fireproof Games）

| | 內容 |
|---|---|
| 為什麼吸引人 | 每個機關都像真實存在的精密物件：可以放大、轉動、拉開、按壓，一層套一層。「目鏡」能看見肉眼看不到的符號。手感與音效回饋極強，觸控裝置上的代表作。 |
| 核心手法 | ① 多層特寫（從房間 → 桌子 → 盒子 → 盒內暗格）② 每個動作都有機械音與動畫回饋 ③ 提示依停滯時間逐步出現 ④ 特殊視覺工具揭露隱藏層 |
| 移植到血色魔鏡 | **視角與特寫系統**（5.1）；**燭光**：長按照亮可互動處、並顯露血字暗紋（取代目鏡）；懷錶齒輪、音樂盒滾筒、縫線盒等「物件型機關」（5.4）；全面加上機關音效與 `navigator.vibrate` 震動回饋。 |
| 不照抄 | 不做 3D 旋轉；以 2D 圖層、CSS 變形與 SVG 達成「打開」「轉動」的感覺，維持零相依。 |

### 2.2 《Rusty Lake》／《Cube Escape》系列（Rusty Lake）

| | 內容 |
|---|---|
| 為什麼吸引人 | 超現實暗黑氛圍；每作很短，但所有作品共用一套隱藏的家族史，玩家會為了拼出全貌而一直玩下去。四面牆的房間切換、物品欄組合、隱藏成就與祕密結局。 |
| 核心手法 | ① 房間四面牆切換 ② 物品欄常駐於畫面底部，選取後點擊場景使用、兩件可組合 ③ 每章有隱藏收集物，集滿解鎖祕密內容 ④ 跨章伏筆：前面看似無用的物件，後面才揭露意義 |
| 移植到血色魔鏡 | **底部物品欄＋組合**（5.2）；**鏡之碎片**：每章藏一片，七片集滿解鎖祕密尾聲「露西的母親」（5.8）；**跨章伏筆清單**（4.3），例如序章的灰兔、第一幕的懷錶在最終審判重新出現。 |
| 不照抄 | 不走純粹獵奇的超現實路線；血色魔鏡的恐怖來自「代價」與「名字被奪走」，保持敘事克制。 |

### 2.3 《The Case of the Golden Idol》（Color Gray Games）

| | 內容 |
|---|---|
| 為什麼吸引人 | 給玩家一個凝結的事件現場，點擊人物、物件與文件會收集「詞彙」；玩家用詞彙填寫事件經過的空格。沒有選項清單，只有自己推理成立時的「頓悟感」。被大量評論稱讚為「讓玩家覺得自己是偵探」。 |
| 核心手法 | ① 文本中的關鍵字可點選收集 ② 填空式結論頁（誰、做了什麼、為什麼）③ 錯誤在兩格以內時只說「差一點」，不指出哪格錯 ④ 不提供逐字答案，提示只引導觀察方向 |
| 移植到血色魔鏡 | **魔鏡審問**（5.3）：每幕結尾以填空陳述「這一幕真正發生了什麼」，詞彙來自熱點文字、物品與對話；最終幕的「最終審判」串起全部章節。主題完美契合：本作的核心就是「揭穿謊言」。 |
| 不照抄 | 不做整幕的靜止現場；填空句子數量收斂在每幕 4–6 格，手機上用點選放置（不必拖曳）。 |

### 2.4 三款共同的成功要素 → 本作設計支柱

| 支柱 | 意思 | 驗收方式 |
|---|---|---|
| **觸得到的祕密** | 每個重要物件都能靠近、操作、得到回饋 | 每幕至少 2 個特寫視角、1 個物件型機關；所有操作有音效 |
| **每個房間都在說謊** | 答案要靠推理，而不是照抄 | 每幕 1 個魔鏡審問；封印答案不再出現在單一熱點的原文中 |
| **代價有回音** | 選擇會被記住，並在尾聲回來 | 至少 4 個選擇點，尾聲與回顧依選擇變化 |
| **哥德式沉浸** | 進入遊戲後，畫面、聲音與文字都屬於魔鏡的世界 | 滿版舞台、標題畫面、主題曲、分軌音訊、無網站外框 |

## 3. 體驗目標

- **一句話**：在一面會說謊的魔鏡裡，親手拼出王國的真相，再決定誰替這份真相付出代價。
- **美感體驗（MDA 的 Aesthetics）**：發現（Discovery）、敘事（Narrative）、挑戰（Challenge）。
- **體驗驗收句**：玩家通關後，能用自己的話說出「契約是怎麼運作的、誰在說謊、為什麼白雪必須交出名字」，而且說得出是哪些線索讓他想通的。
- **時長**（首次通關、不看最終答案級提示）：

| 玩家類型 | A 階段後 | B 階段後 |
|---|---|---|
| 快速（熟悉解謎） | 32–38 分 | 42–50 分 |
| 一般 | 40–50 分 | 55–65 分 |
| 全收集（碎片、記憶、三結局） | 60–70 分 | 75–90 分 |

## 5. 核心玩法系統

### 5.1 視角與特寫系統（Views）

- 每章由多個 `view` 組成：全景視角可左右切換（箭頭、鍵盤 ←／→、手機左右滑），特寫視角從全景中的框選區域放大進入，以返回鍵或下滑離開。
- 轉場：全景間以 220ms 交叉淡化；進入特寫以「鏡頭推近」縮放（`prefers-reduced-motion` 時改為淡化）。
- 特寫圖來源：優先使用同一張場景原圖的高解析裁切（成本最低），重要物件（書桌、棺蓋、縫線盒、懷錶內部）才產生新圖。
- 熱點座標以「圖片空間百分比」記錄（沿用目前 `x`、`y`），新增可選的 `w`、`h` 或多邊形 `area`，以便框選物件而不只是點。

### 5.2 物品系統升級

- **常駐底部物品欄**（取代側欄清單）：手機 5 格、桌面 6 格，超出可左右捲。
- **使用**：點選物品（高亮）→ 點場景熱點。錯誤使用時，白雪用一句話回應（例如「懷錶不是鑰匙」），不扣分。
- **組合**：在物品欄中先後點選兩件，或在物品檢視畫面拖曳到另一件。例：銅製閥柄＋扳手 → 可轉動的閥柄；銀針＋紅線 → 縫線工具。
- **檢視**：物品可翻面（正面／背面兩張圖或 SVG），背面常藏線索詞，例如懷錶背蓋的刻字。

### 5.3 魔鏡審問（真相推理）

- **線索詞**：熱點、物品與對話文字中，以虛線底標示的詞可點選收入「推理簿」，同時跳出一則提示「新線索詞：第十三聲」。
- **審問頁**：4–6 個空格的陳述句；詞庫依「人物／數字與時間／物件／動作」分組。點空格 → 點詞（或拖曳）放入。
- **判定**：全部填滿才能「向魔鏡陳述」。全對 → 鏡面裂開動畫＋封印開啟；錯 1–2 格 → 魔鏡只說「還有兩個謊言」；錯 3 格以上 → 只說「妳的陳述仍被謊言包圍」。不告訴玩家哪一格錯。
- **與舊封印的關係**：四位密碼、開閥順序、符印順序等仍保留為「動手」的機關，但答案改為從審問結論推得，而不是在某個熱點原文中直接寫出。
- **最終審判**（第七幕）：三段陳述、共 12–15 格，詞彙跨所有章節，是全作的推理高潮；完成後才進入最終抉擇。

## 9. 技術架構調整

### 9.1 原則

- 維持**零執行期相依**、原生 ES 模組、不引入打包工具。

### 9.4 效能與資產預算

- **按章節延遲載入**：只預先載入目前章節與下一章的全景；特寫、立繪在進入該章時載入。首屏只需標題主視覺＋前奏循環（約 0.9 MB）。
- 圖片：WebP（必要時 AVIF），單張 ≤ 300 KB（既有規則 500 KB 不變）。
- 動畫：只動 `transform` 與 `opacity`；粒子（雪、燭火餘燼）用單一 `<canvas>`，數量依裝置效能調降，減少動畫時關閉。
- 互動延遲：點擊到回饋 < 100 ms；章節切換 < 1 秒（已預載時）。
- `dist/games` 預估從 10 MB 增加到約 22–26 MB（新場景、立繪、主題曲、加長配樂），需要決策 D1。

每個里程碑一個分支、一個 PR，可以獨立合併與回退。工作量以 S（≤ 半天）、M（1–2 天）、L（3–5 天）粗估，實際以第一個里程碑的速度校正。
